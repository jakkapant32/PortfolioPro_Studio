## 3. โครงสร้างโฟลเดอร์

```
PortfolioPro Studio/
├── frontend/          React + Vite (หน้าเว็บ)
├── backend/           Golang + Gin + GORM (API)
├── docs/              เอกสารรายงาน
├── preview/           ไฟล์ทดลอง UI (เช่น hero-carousel)
├── scripts/           สคริปต์เซ็ตอัพเครื่อง local
├── render.yaml        Blueprint deploy backend + PostgreSQL บน Render
├── docker-compose.yml PostgreSQL สำหรับพัฒนา
└── README.md
```

**รันบนเครื่องพัฒนา**
- Frontend: `cd frontend` → `npm run dev` → http://localhost:5173
- Backend: `cd backend` → `go run main.go` → พอร์ตจาก `.env` คือ **8081** ในเครื่องนี้ (ค่าเริ่มต้นในโค้ดถ้าไม่ใส่ PORT คือ **8080**)
- ฐานข้อมูล: PostgreSQL ชื่อ `portfoliopro`
- Docker: `docker-compose.yml` ใช้ Postgres 16 พอร์ต 5432 user/password `postgres`

## 4. สถาปัตยกรรม

```
เบราว์เซอร์
    │
    ▼
Frontend (React)  ──►  Vercel
    │  REST JSON + JWT
    ▼
Backend (Go/Gin)  ──►  Render Web Service
    │
    ├── PostgreSQL     ──►  Render Database
    ├── Omise API      ──►  ชำระเงิน / webhook
    └── SMTP (ถ้าตั้ง) ──►  อีเมลแจ้งเตือน
```

- แยก Frontend กับ Backend คนละโฮสต์
- ราคาตอนคิดเงิน **ดึงจากฐานข้อมูลฝั่งเซิร์ฟเวอร์** ไม่เชื่อราคาที่ส่งมาจากเบราว์เซอร์
- Production CORS อนุญาตเฉพาะโดเมนที่กำหนด; ตอน dev อนุญาต IP ใน LAN ด้วย (เปิดมือถือใน WiFi เดียวกันได้)

**แผน Deploy ที่ตกลงไว้**
1. Backend บน Render → ได้ URL เช่น `https://portfoliopro-api.onrender.com`
2. ใส่เป็น `VITE_API_URL` แล้ว deploy Frontend บน Vercel
3. ชี้โดเมนที่ Vercel
4. ตั้ง `ALLOWED_ORIGINS` บน Render ให้ตรงโดเมนจริง

| สไตล์ | CSS ไฟล์ `global.css`, `hero-carousel.css` |

### Backend
| รายการ | ของที่ใช้ |
|--------|-----------|
| ภาษา | Go 1.21 |
| เฟรมเวิร์ก | Gin |
| ORM | GORM |
| DB | PostgreSQL |
| Auth | JWT (`github.com/golang-jwt/jwt/v5`) |
| รหัสผ่าน | bcrypt (`golang.org/x/crypto`) |
| CORS | gin-contrib/cors |
| Env | godotenv |

### ความปลอดภัยที่มีในโค้ด
- JWT บังคับก่อนสั่งซื้อ / ดูออเดอร์ / เข้าแอดมิน
- Role `customer` และ `admin` (แอดมินต้องผ่าน `AdminRequired`)
- Rate limit เช่น สมัคร 10 ครั้ง/15 นาที, ล็อกอิน 15 ครั้ง/15 นาที, ติดต่อ 5 ครั้ง/ชั่วโมง
- จำกัดขนาด body 1 MB
- Security headers
- รหัสผ่านอย่างน้อย 8 ตัว ต้องมีทั้งตัวอักษรและตัวเลข
- ใน production ห้ามใช้ JWT_SECRET ค่า dev และต้องยาวอย่างน้อย 32 ตัว

## 9. ระบบสมาชิกและสิทธิ์

| Role | ความหมาย |
|------|----------|
| `customer` | ลูกค้าทั่วไป (ค่าเริ่มต้นตอนสมัคร) |

## 10. ระบบร้านค้าและการเงิน (จุดขายของเล่ม E-commerce)

### ตะกร้า
- เพิ่มแพ็กเกจจากกริดหรือหน้า detail  
- ซ้ำรายการเดิมจะแจ้งว่ามีในตะกร้าแล้ว  
- คิดยอดฝั่งเซิร์ฟเวอร์จากราคาที่ publish ในฐานข้อมูล

### รูปแบบการชำระ
| ตัวเลือก | ความหมายในระบบ |
|----------|-----------------|
| ชำระเต็ม 100% | คิวด่วน เริ่มภายใน 1–2 วันทำการ (แนะนำ) |
| มัดจำ 50% | คิวปกติ เริ่ม 3–5 วันทำการ |
| มัดจำ 30% | คิวรอ เริ่ม 7–14 วันทำการ |

ยอดที่คิด = ราคารวม × เปอร์เซ็นต์มัดจำ  
ถ้ามัดจำไม่ครบ ลูกค้าจ่ายยอดคงเหลือทีหลังได้ (`PayOrderBalance`)

### ช่องทางจ่าย
- PromptPay QR (Omise ตรวจอัตโนมัติ) — Omise กำหนดยอดขั้นต่ำประมาณ 20 บาท  
- บัตร Visa / Mastercard / JCB  
- Mobile Banking / Internet Banking ตามที่ Omise รองรับ  
- QR สำรอง (สร้างด้วยเบอร์ PromptPay) เมื่อยังไม่ตั้ง Omise หรือยอดต่ำกว่าขั้นต่ำ — ให้ส่งสลิปทาง Line

### สถานะออเดอร์ที่ลูกค้าเห็น (ตัวอย่าง)
- pending  
- deposit_paid (มัดจำแล้ว)  
- successful  
และอื่นๆ ตามที่ backend ตั้งใน `order_status`

### ฟิลด์ออเดอร์หลัก
ลูกค้า, รายการ, ยอดก่อนลด, ส่วนลด, คูปอง, ยอดสุทธิ, เปอร์เซ็นต์มัดจำ, ยอดที่จ่ายแล้ว, วิธีจ่าย, สถานะ, รหัส Omise, QR, วันเวลาจ่าย

## 11. วงจรงานหลังขาย (Project / ส่งมอบ)

สร้างโปรเจกต์จากออเดอร์ได้ที่แอดมิน

**สถานะโปรเจกต์**
- pending
- contract_sent
- contract_accepted
- in_progress
- delivered
- completed

**สัญญา (Contract):** draft → sent → accepted (ลูกค้ากดยอมรับ ระบบเก็บ IP)  
**การส่งมอบ (Delivery):** draft → sent → received (ลูกค้ารับงาน)

ลูกค้าทำได้ที่ `/my-projects`:
- ยอมรับสัญญา
- ยืนยันรับงานส่งมอบ

## 15. ตัวแปรสภาพแวดล้อมที่ต้องรู้ตอน Deploy

### Frontend (`VITE_...` ใส่ตอน build บน Vercel)
| ตัวแปร | ความหมาย |
|--------|----------|
| `VITE_API_URL` | URL backend Render (ถ้าไม่ใส่ ระบบใช้ hostname ปัจจุบัน + พอร์ต 8081 — เหมาะกับ dev/LAN) |
| `VITE_API_PORT` | ค่าเริ่ม 8081 |
| `VITE_SITE_URL` | โดเมนเว็บ เช่น https://portfoliopro.studio |
| `VITE_GA_ID` | Google Analytics (ถ้ามี) |
| `VITE_CLARITY_ID` | Microsoft Clarity (ถ้ามี) |

ไฟล์ตั้งค่า Vercel: `frontend/vercel.json` (SPA rewrite + security headers)

### Backend (Render)
| ตัวแปร | ความหมาย |
|--------|----------|
| `PORT` | Render กำหนดให้เอง |
| `GIN_MODE` | release |
| `JWT_SECRET` | รหัสเซ็นโทเคน (สุ่มใน render.yaml) |
| `DATABASE_URL` | มาจาก PostgreSQL ของ Render |
| `ALLOWED_ORIGINS` | โดเมน frontend คั่นด้วยจุลภาค |
| `OMISE_SECRET_KEY` / `OMISE_PUBLIC_KEY` | คีย์รับเงิน |
| `OMISE_WEBHOOK_SECRET` | ตรวจ webhook |
| `ADMIN_EMAIL` | อีเมลได้สิทธิ์แอดมิน |
| `SITE_URL` | ลิงก์ในอีเมล |
| SMTP_* | ส่งเมลเมื่อจ่ายสำเร็จ (ไม่ใส่ก็ข้าม แล้ว log) |

`render.yaml` สร้างบริการชื่อ `portfoliopro-api` และฐาน `portfoliopro-db`  
Build: `go build -o server .`  
Start: `./server`  
Health: `/api/health`

**หมายเหตุแผนฟรี Render:** API อาจหลับถ้าไม่มีคนใช้ ประมาณ 15 นาที ครั้งแรกจะช้า

## 17. ขั้นตอนธุรกิจที่ลูกค้าเจอ (ใช้เขียนคู่มือซื้อ)

1. เปิดเว็บ  
2. สมัคร / เข้าสู่ระบบ  
3. เลือกแพ็กเกจที่ `/portfolio` หรือหน้าแรก  
4. เพิ่มลงตะกร้า  
5. เปิดตะกร้า → ใส่คูปองได้ → เลือกมัดจำ 100/50/30%  
6. เลือกช่องทางจ่าย → สแกน QR หรือตัดบัตร  
7. ดูสถานะที่คำสั่งซื้อของฉัน  
8. เมื่อร้านสร้างโปรเจกต์ → ยอมรับสัญญา → รับงานส่งมอบที่งานของฉัน  
9. หรือขอใบเสนอราคาก่อนถ้างานสั่งทำพิเศษ  

## ขั้นตอนที่ผู้ขายเจอ (ใช้เขียนคู่มือขาย)

1. เข้า `/admin`  
2. ดูออเดอร์ที่จ่ายแล้ว  
3. สร้างโปรเจกต์จากออเดอร์  
4. ส่งสัญญา → ลูกค้าตอบรับ  
5. ทำงาน → ส่งมอบลิงก์/ข้อความ → ลูกค้ารับงาน  
6. ดูรายงานยอด  
7. จัดการแพ็กเกจ บทความ คูปอง ข้อความติดต่อ

## 18. FAQ ที่อยู่ในเว็บ (ตัดมาใช้ในเล่มได้)

**รับทำอะไรบ้าง**  
Portfolio Website, Corporate Website, ระบบธุรกิจ เช่น CRM, E-commerce, LMS

**ใช้เวลานานแค่ไหน**  
Portfolio โดยทั่วไปใน FAQ เขียน 7–14 วัน (ในแพ็กเกจจบใหม่ระบุ 3–5 วัน) Corporate/ระบบ 2–6 สัปดาห์ ตามแพ็กเกจ

**แก้กี่รอบ**  
ตามที่ระบุในแพ็กเกจ

**ช่องทางจ่าย**  
PromptPay QR, บัตร, Mobile/Internet Banking ผ่าน Omise อัปเดตสถานะอัตโนมัติ

**หลังจ่ายได้อะไร**  
อีเมลยืนยันถ้าตั้ง SMTP แล้ว ทีมงานติดต่อเก็บข้อมูลแล้วเริ่มงาน

**ขอใบเสนอราคาก่อนได้**  
ได้ ตอบภายใน 24 ชั่วโมง (ตามข้อความบนเว็บ)

**ยกเลิก/คืนเงิน**  
ยังไม่เริ่มงานแจ้งยกเลิกได้ทางเมลหรือ Line ถ้าเริ่มแล้วคิดตามความคืบหน้า

## 19. สิ่งที่ยังไม่ใช่ / นอกขอบเขต (อย่าเขียนเกินจริงในเล่ม)

- ไม่ใช่ร้านขายสินค้าส่งพัสดุ  
- ไม่มีแอป iOS/Android แยก  
- ไม่ใช่ระบบบัญชี/ภาษีเต็มรูปแบบ  
- แพ็กเกจ CRM / เช่ารถ / LMS / ร้านค้าบนหน้าร้านคือ **บริการที่รับทำ** ไม่ได้แปลว่าระบบเหล่านั้นถูกรันครบในโดเมนนี้  
- สถิติ 150+ โปรเจกต์ / 98% คือข้อความการตลาดบนหน้าแรก  
- ลิงก์โปรดักชันจริงยังขึ้นกับว่า Deploy แล้วหรือยัง — ตอนทำเล่มใส่ URL หลังขึ้น Vercel/Render แล้ว  
- ภาพแพ็กเกจบางรายการมาจาก Unsplash ต้องอ้างอิงถ้าใช้ในเล่ม

## 20. ประโยคสรุปสั้นๆ สำหรับบทนำ

PortfolioPro Studio เป็นเว็บแอปพลิเคชันธุรกิจพาณิชย์อิเล็กทรอนิกส์ ด้านรับออกแบบและพัฒนาเว็บไซต์ Portfolio เว็บองค์กร และระบบงานธุรกิจ ระบบแบ่งเป็นส่วนแสดงผลด้วย React กับส่วนบริการด้วย Golang และฐานข้อมูล PostgreSQL ลูกค้าเลือกแพ็กเกจ ใส่ตะกร้า ชำระเงินออนไลน์ผ่าน PromptPay หรือบัตร (Omise) แล้วติดตามคำสั่งซื้อและงานส่งมอบได้ ผู้ดูแลระบบจัดการออเดอร์ เนื้อหา คูปอง และรายงานผ่านแผงควบคุม แผนนำขึ้นอินเทอร์เน็ตคือ Frontend บน Vercel และ Backend บน Render
