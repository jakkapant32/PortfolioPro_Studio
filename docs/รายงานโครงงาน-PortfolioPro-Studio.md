# คำนำ

รายงานฉบับนี้จัดทำขึ้นเพื่อนำเสนอการพัฒนาเว็บไซต์ **PortfolioPro Studio** ซึ่งเป็นระบบธุรกิจออนไลน์สำหรับรับออกแบบและพัฒนาเว็บไซต์ Portfolio ส่วนบุคคล เว็บไซต์องค์กร และระบบงานธุรกิจ พร้อมร้านค้าบริการ (แพ็กเกจ) ตะกร้าสินค้า ระบบสมาชิก และชำระเงินออนไลน์ผ่าน PromptPay QR / Omise

ผู้จัดทำมุ่งพัฒนาให้ระบบใช้งานได้จริงทั้งฝั่งลูกค้าและฝั่งผู้ดูแลระบบ ตั้งแต่การนำเสนอสินค้าบริการ การสั่งซื้อ การชำระเงิน การติดตามคำสั่งซื้อ ไปจนถึงแผงควบคุมหลังบ้าน

ขอขอบคุณอาจารย์ที่ปรึกษา ผู้ปกครอง และผู้ที่เกี่ยวข้องที่ให้คำแนะนำจนโครงงานสำเร็จเป็นรูปเล่มและระบบออนไลน์

หากรายงานหรือระบบมีข้อบกพร่องประการใด ผู้จัดทำขออภัยมา ณ ที่นี้ และยินดีรับคำชี้แนะเพื่อพัฒนาต่อไป

# บทที่ 1  
# บทนำ

## 1.1 หลักการและเหตุผล

ในยุคดิจิทัล การสมัครงานและการสร้างภาพลักษณ์ทางวิชาชีพไม่สามารถพึ่งพาเพียงแฟ้มผลงานกระดาษหรือไฟล์ PDF ได้อีกต่อไป นายจ้างและลูกค้าต้องการเห็นผลงาน ทักษะ และตัวตนของผู้สมัครผ่านช่องทางออนไลน์ที่เข้าถึงได้ทันที นักศึกษาจบใหม่ ฟรีแลนซ์ และผู้ประกอบการจำนวนมากยังไม่มีเว็บไซต์ส่วนตัวที่เป็นมืออาชีพ หรือไม่ทราบจะเริ่มพัฒนาอย่างไร

ขณะเดียวกัน ผู้ให้บริการรับทำเว็บไซต์มักนำเสนอผลงานผ่านโซเชียลมีเดียหรือการคุยทางแชทเป็นหลัก ทำให้ลูกค้าเลือกแพ็กเกจ เปรียบเทียบราคา สั่งซื้อ และชำระเงินได้ไม่สะดวก ขาดระบบตะกร้า คำสั่งซื้อ และการติดตามงานแบบรวมศูนย์

ผู้จัดทำจึงพัฒนา **PortfolioPro Studio** เป็นเว็บไซต์ธุรกิจพาณิชย์อิเล็กทรอนิกส์ที่ทำหน้าที่สองด้านพร้อมกัน คือ

1. **หน้าร้านออนไลน์** สำหรับเลือกแพ็กเกจบริการ (Portfolio Website, Corporate Website, ระบบธุรกิจ) ใส่ตะกร้า ชำระเงิน และติดตามคำสั่งซื้อ  
2. **ระบบหลังบ้าน** สำหรับผู้ขายในการจัดการออเดอร์ ลูกค้า เนื้อหา บทความ คูปอง และรายงานยอดขาย

ระบบนี้ตอบโจทย์ทั้งผู้ซื้อที่ต้องการจ้างทำเว็บไซต์ และผู้ขายที่ต้องการช่องทางจำหน่ายบริการแบบออนไลน์ครบวงจร

## 1.2 วัตถุประสงค์

1. เพื่อพัฒนาเว็บไซต์ธุรกิจรับทำ Portfolio และบริการที่เกี่ยวข้อง ให้ลูกค้าเลือกแพ็กเกจและสั่งซื้อออนไลน์ได้  
2. เพื่อพัฒนาระบบสมาชิก ตะกร้าสินค้า การชำระเงิน และการติดตามคำสั่งซื้อ  
3. เพื่อพัฒนาระบบผู้ดูแลระบบสำหรับจัดการสินค้า เนื้อหา ออเดอร์ และการขาย  
4. เพื่อนำเว็บไซต์ขึ้นใช้งานจริงบนอินเทอร์เน็ต และจัดทำคู่มือการใช้งานพร้อมตัวอย่างรายการซื้อ–ขาย

## 1.3 ขอบเขตของโครงงาน

**ตารางที่ 1.1 ขอบเขตฟังก์ชันของระบบ**

| ฝั่ง | ฟังก์ชันที่พัฒนา |
|------|------------------|
| ลูกค้า (ผู้ซื้อ) | สมัครสมาชิก / เข้าสู่ระบบ, ดูหน้าแรกและบริการ, เลือกแพ็กเกจ, ตะกร้า, ชำระเงิน, ดูคำสั่งซื้อ, ดูงานของฉัน, ติดต่อขอใบเสนอราคา |
| ผู้ขาย / แอดมิน | แดชบอร์ด, ออเดอร์, โปรเจกต์ส่งมอบ, คูปอง, ข้อความติดต่อ, ใบเสนอราคา, ผู้ใช้, คลังผลงาน, บทความ, ตั้งค่าเว็บไซต์ |
| ระบบ | API Golang, ฐานข้อมูล PostgreSQL, การยืนยันตัวตนด้วย JWT, ชำระเงิน PromptPay / Omise |

**นอกขอบเขต**  
ไม่ครอบคลุมการขนส่งสินค้ากายภาพ (เพราะขายบริการดิจิทัล) ไม่ครอบคลุมแอปมือถือแบบ Native และไม่ครอบคลุมการทำบัญชีภาษีเต็มรูปแบบ

## 1.4 ประโยชน์ที่คาดว่าจะได้รับ

1. ลูกค้าเลือกและสั่งซื้อแพ็กเกจได้ตลอด 24 ชั่วโมง  
2. ผู้ประกอบการมีระบบรับออเดอร์และจัดการงานแบบรวมศูนย์  
3. ผู้จัดทำได้ฝึกกระบวนการพัฒนาเว็บพาณิชย์อิเล็กทรอนิกส์ตั้งแต่วิเคราะห์ ออกแบบ พัฒนา ทดสอบ Deploy และจัดทำเอกสาร  
4. ได้เว็บไซต์ออนไลน์ที่นำไปใช้เป็นผลงานและช่องทางธุรกิจจริงได้

## 1.5 นิยามศัพท์เฉพาะ

| คำ | ความหมายในโครงงานนี้ |
|----|------------------------|
| E-commerce | การซื้อขายบริการผ่านเว็บไซต์ รวมตะกร้าและชำระเงินออนไลน์ |
| แพ็กเกจ | สินค้าบริการที่ขายบนเว็บ เช่น Portfolio นักศึกษาจบใหม่ |
| PromptPay | การชำระเงินด้วย QR ผ่านแอปธนาคาร |
| Omise | ผู้ให้บริการรับชำระเงินออนไลน์ที่ระบบเชื่อมต่อ |
| Deploy | การนำระบบขึ้นเซิร์ฟเวอร์ให้เข้าถึงจากอินเทอร์เน็ต |
| Frontend | ส่วนเว็บที่ผู้ใช้เห็น พัฒนาด้วย React |
| Backend | ส่วน API และการประมวลผล พัฒนาด้วย Golang |

## 2.1 การวิเคราะห์ความต้องการ

### 2.1.1 กลุ่มผู้ใช้

| กลุ่ม | ความต้องการ |
|-------|-------------|
| นักศึกษาจบใหม่ / คนหางาน | Portfolio ที่ดูเป็นมืออาชีพ สมัครงานได้ |
| ฟรีแลนซ์ | โชว์ผลงาน รับงาน สร้างความน่าเชื่อถือ |
| วัยทำงาน / ผู้ทรงคุณวุฒิ | เว็บส่วนตัวหรือภาพลักษณ์องค์กร |
| SME | เว็บบริษัทและระบบงาน เช่น CRM, ร้านค้า, เช่ารถ |
| ผู้ดูแลร้าน (ผู้ขาย) | รับออเดอร์ ดูยอด จัดการลูกค้าและเนื้อหา |

### 2.1.2 ความต้องการเชิงฟังก์ชัน (Functional Requirements)

- แสดงหน้าแรก บริการ ผลงาน บทความ FAQ และติดต่อ  
- สมัครสมาชิก เข้าสู่ระบบ แก้ไขโปรไฟล์  
- เลือกแพ็กเกจ ใส่ตะกร้า คิดราคา รวมคูปอง  
- ชำระเงินออนไลน์ แล้วดูสถานะคำสั่งซื้อ  
- ผู้ดูแลจัดการออเดอร์ โปรเจกต์ บทความ และรายงาน

### 2.1.3 ความต้องการเชิงคุณภาพ (Non-functional)

- รองรับมือถือและคอมพิวเตอร์  
- แยก Frontend กับ Backend เพื่อขยายระบบได้  
- มีการยืนยันตัวตนก่อนสั่งซื้อและเข้าหลังบ้าน  
- Deploy แยกส่วน: เว็บบน Vercel, API และฐานข้อมูลบน Render

## 2.2 การออกแบบระบบ

### 2.2.1 สถาปัตยกรรม

ระบบเป็นแบบ **แยกส่วน (Decoupled)**

```
ผู้ใช้ (เบราว์เซอร์ / มือถือ)
        │
        ▼
Frontend  React + Vite     ── Deploy ที่ Vercel
        │  HTTP/JSON
        ▼
Backend   Golang (Gin)     ── Deploy ที่ Render
        │
        ▼
PostgreSQL                 ── Render Database
        │
        ▼
Omise (ชำระเงิน) + อีเมลแจ้งเตือน (ถ้าตั้งค่า SMTP)
```

**ภาพที่ 2.1** แผนภาพสถาปัตยกรรมระบบ *(วาด/Capture ใส่ในเล่ม)*

### 2.2.3 การไหลของการซื้อขาย

```
เข้าเว็บ → สมัคร/เข้าสู่ระบบ → เลือกแพ็กเกจ → เพิ่มลงตะกร้า
→ เปิดตะกร้า → ชำระเงิน (PromptPay QR / บัตร / โอน)
→ ระบบสร้างคำสั่งซื้อ → แจ้งเตือนแอดมิน
→ ลูกค้าดูสถานะที่ “คำสั่งซื้อของฉัน”
→ แอดมินจัดการงานที่แผงควบคุม → ส่งมอบงาน
```

**ภาพที่ 2.2** แผนภาพการไหลของการสั่งซื้อ *(ใส่ในเล่ม)*

## 2.4 ขั้นตอนการพัฒนา (ทีละขั้น)

ขั้นตอนนี้นำไปเขียนในเล่มเป็นลำดับเวลาจริงของโครงงาน

### ขั้นที่ 1 ศึกษาและกำหนดหัวข้อ
ศึกษาปัญหาการไม่มีช่องทางสั่งทำเว็บไซต์แบบออนไลน์ครบวงจร กำหนดชื่อธุรกิจ PortfolioPro Studio และกลุ่มลูกค้า 4 กลุ่ม ได้แก่ นักศึกษาจบใหม่ ฟรีแลนซ์ วัยทำงาน และผู้ทรงคุณวุฒิ

### ขั้นที่ 2 วิเคราะห์และออกแบบ
ออกแบบหน้าเว็บ เมนู ตะกร้า ระบบสมาชิก แผงแอดมิน และฐานข้อมูล แยก Frontend กับ Backend

### ขั้นที่ 3 พัฒนา Frontend
- สร้างโครง React + เส้นทางหน้าเว็บ  
- ทำหน้าแรก บริการ เกี่ยวกับเรา ติดต่อ FAQ บทความ  
- ทำ Hero Carousel ตามกลุ่มเป้าหมาย  
- ทำคลังแพ็กเกจ รายละเอียดสินค้า ตะกร้า Checkout  
- ทำหน้าคำสั่งซื้อของฉัน และงานของฉัน  

### ขั้นที่ 4 พัฒนา Backend
- สร้าง API ด้วย Golang (ลงทะเบียน เข้าสู่ระบบ ข้อมูลเว็บ ออเดอร์ การชำระเงิน)  
- เชื่อม PostgreSQL  
- เชื่อม Omise สำหรับ PromptPay และการตรวจสถานะอัตโนมัติ  
- ทำสิทธิ์แอดมินและ API หลังบ้าน  

### ขั้นที่ 5 พัฒนาแผงผู้ขาย (Admin)
แดชบอร์ด รายงาน ออเดอร์ โปรเจกต์ คูปอง ข้อความติดต่อ ใบเสนอราคา ผู้ใช้ คลังผลงาน บทความ และการตั้งค่าเว็บไซต์

### ขั้นที่ 6 ทดสอบ
ทดสอบบนคอมพิวเตอร์และมือถือในเครือข่ายเดียวกัน ทดสอบสมัครสมาชิก ใส่ตะกร้า ชำระเงินโหมดทดสอบ และเข้าหลังบ้าน

### ขั้นที่ 7 Deploy ขึ้นอินเทอร์เน็ต
1. Push โค้ดขึ้น GitHub  
2. Deploy **Backend บน Render** (API + PostgreSQL) ได้ URL เช่น `https://portfoliopro-api.onrender.com`  
3. ตั้ง `VITE_API_URL` เป็น URL นั้น  
4. Deploy **Frontend บน Vercel**  
5. ชี้โดเมนที่ Vercel เช่น `https://portfoliopro.studio`  
6. ตั้ง `ALLOWED_ORIGINS` บน Render ให้ตรงโดเมนจริง  

### ขั้นที่ 8 จัดทำเอกสารและส่งงาน
จัดทำรูปเล่มตามเค้าโครง ใส่ลิงก์เว็บในรายงาน และนำไปติดบน **Padlet หรือบอร์ดออนไลน์ที่อาจารย์กำหนด**

# คู่มือการใช้งานระบบ

คู่มือนี้ใช้ประกอบการสอบ/ตรวจงาน แสดงวิธีซื้อของลูกค้า และวิธีขาย/จัดการของผู้ดูแลระบบ  
ให้แทรกภาพหน้าจอทุกขั้นตอน

## ก. คู่มือลูกค้า (ฝั่งผู้ซื้อ)

### ก.1 เปิดเว็บไซต์
1. เปิดเบราว์เซอร์  
2. เข้า `[ลิงก์เว็บจริง]`  
3. พบหน้าแรก มีตัวละครกลุ่มเป้าหมาย และเมนู หน้าแรก / คลังผลงานและบริการ / เกี่ยวกับเรา / ติดต่อ  

### ก.2 สมัครสมาชิกและเข้าสู่ระบบ
1. กด **เข้าสู่ระบบ** มุมขวาบน  
2. หากยังไม่มีบัญชี กดสมัคร แล้วกรอกชื่อ อีเมล รหัสผ่าน (อย่างน้อย 8 ตัว มีทั้งตัวอักษรและตัวเลข)  
3. เข้าสู่ระบบสำเร็จ จะเห็นชื่อบัญชีแทนปุ่มเข้าสู่ระบบ  

### ก.3 เลือกบริการและใส่ตะกร้า
1. กดเมนู **คลังผลงานและบริการ**  
2. เลือกแพ็กเกจ เช่น “Portfolio นักศึกษาจบใหม่” หรือแพ็กเกจทดสอบ 20 บาท  
3. กด **เพิ่มลงตะกร้า**  
4. หากยังไม่เข้าสู่ระบบ ระบบจะให้เข้าสู่ระบบก่อน  

### ก.4 ชำระเงิน
1. กดไอคอนตะกร้า มุมขวาบน  
2. ตรวจรายการและยอดรวม (ใส่คูปองได้ถ้ามี)  
3. กดชำระเงิน เลือกช่องทาง เช่น PromptPay QR  
4. สแกน QR ด้วยแอปธนาคาร  
5. รอสถานะสำเร็จ แล้วไปที่ **คำสั่งซื้อของฉัน**  

### ก.5 ติดตามงาน
- **คำสั่งซื้อของฉัน** (`/my-orders`) ดูประวัติชำระเงิน  
- **งานของฉัน** (`/my-projects`) ดูงานที่ร้านกำลังทำให้  
- หากต้องการคุยกับร้าน กดปุ่ม Line หรือหน้าติดต่อ  

### ก.6 ขอใบเสนอราคา
ใช้เมื่อต้องการงานที่ไม่มีในแพ็กเกจสำเร็จรูป  
1. กด **ขอใบเสนอราคา** หรือเข้าหน้าติดต่อ  
2. กรอกความต้องการ แล้วส่ง  
3. แอดมินจะเห็นรายการในหลังบ้าน  

## ข. คู่มือผู้ดูแลระบบ (ฝั่งผู้ขาย)

### ข.1 เข้าสู่ระบบหลังบ้าน
1. เปิด `[ลิงก์เว็บ]/admin`  
2. เข้าสู่ระบบด้วยบัญชีที่กำหนดเป็นแอดมิน (อีเมลใน `ADMIN_EMAIL`)  
3. เข้าแผงควบคุม  

### ข.2 ดูยอดขายและออเดอร์
- **ภาพรวม** ดูสถิติ  
- **คำสั่งซื้อ** ดูออเดอร์ที่ลูกค้าชำระแล้ว  
- **รายงาน** ดูสรุปช่องทางชำระเงิน  

### ข.3 จัดการงานส่งมอบ
ที่เมนู **โปรเจกต์/ส่งมอบ** อัปเดตสถานะงานให้ลูกค้าเห็นในหน้า “งานของฉัน”

### ข.4 จัดการหน้าร้าน
- **คลังผลงาน** เพิ่ม/แก้แพ็กเกจ ราคา คำอธิบาย  
- **บทความ** เพิ่มเนื้อหา SEO  
- **คูปอง** สร้างโค้ดส่วนลด  
- **ตั้งค่า** แก้เบอร์โทร Line PromptPay โซเชียล  

### ข.5 จัดการลูกค้า
ดูข้อความจากฟอร์มติดต่อ ใบเสนอราคา และรายชื่อผู้ใช้

## ค. ตัวอย่างการทำรายการซื้อ–ขาย

ใช้เป็นสคริปต์สาธิตตอนสอบหรือใส่ภาพในเล่ม

### ตัวอย่างที่ 1 ลูกค้าซื้อแพ็กเกจทดสอบ (ธุรกรรมซื้อ)

**สถานการณ์:** นายเอ ต้องการทดลองจ่ายเงิน 20 บาท เพื่อดูว่าระบบ QR ทำงาน

1. นายเอเปิดเว็บไซต์ แล้วสมัครสมาชิกด้วยอีเมลของตนเอง  
2. เข้า **คลังผลงานและบริการ** เลือกสินค้า **ทดสอบ Omise (฿20)**  
3. กดเพิ่มลงตะกร้า เปิดตะกร้า ยอดรวม 20 บาท  
4. กดชำระเงิน เลือก PromptPay  
5. สแกน QR ด้วยแอปธนาคาร (โหมดทดสอบของ Omise ตามคู่มือผู้ให้บริการ)  
6. ระบบบันทึกคำสั่งซื้อ นายเอเปิด **คำสั่งซื้อของฉัน** แล้วเห็นรายการ  

**ภาพที่ ค.1–ค.3** ใส่แคปหน้าจอขั้นตอนข้างต้น

### ตัวอย่างที่ 2 ลูกค้าสั่งทำ Portfolio (ธุรกรรมซื้อบริการจริง)

**สถานการณ์:** นางสาวบี จบใหม่ ต้องการเว็บ Portfolio ราคา 3,500 บาท

1. สมัครสมาชิกและเข้าสู่ระบบ  
2. เปิดแพ็กเกจ **Portfolio นักศึกษาจบใหม่** อ่านรายละเอียด ระยะส่ง 3–5 วัน

# ภาคผนวก

## ภาคผนวก ก โครงสร้างโปรเจกต์และหน้าจอหลัก

```
PortfolioPro Studio/
├── frontend/          เว็บ React (Vercel)
├── backend/           API Golang (Render)
├── docs/              เอกสารรายงาน
├── render.yaml        Blueprint ของ Render
└── docker-compose.yml
```

ให้แนบภาพหน้าจออย่างน้อยดังนี้  
1. หน้าแรก  
2. หน้าร้านแพ็กเกจ  
3. ตะกร้าและ QR ชำระเงิน  
4. คำสั่งซื้อของฉัน  
5. แดชบอร์ดแอดมิน  
6. หน้า Padlet ที่มีลิงก์เว็บ *(หลักฐานส่งงาน)*

## ภาคผนวก ข API หลักของระบบ

| Method | Path | ผู้ใช้ |
|--------|------|--------|
| GET | `/api/health` | สาธารณะ |
| POST | `/api/auth/register` | สาธารณะ |
| POST | `/api/auth/login` | สาธารณะ |
| GET | `/api/portfolio` | สาธารณะ |
| POST | `/api/payments` | สมาชิก |
| GET | `/api/my-orders` | สมาชิก |
| GET | `/api/my-projects` | สมาชิก |
| POST | `/api/contact` | สาธารณะ |
| กลุ่ม `/api/admin/...` | ผู้ดูแลระบบ | |

## ภาคผนวก ค การตั้งค่า Deploy

**Vercel (Frontend)**  
- Root Directory: `frontend`  
- `VITE_API_URL` = URL ของ Render  
- `VITE_SITE_URL` = โดเมนจริง  

**Render (Backend)**  
- Blueprint จาก `render.yaml`  
- `GIN_MODE=release`  
- `DATABASE_URL` จาก PostgreSQL ของ Render  
- `ALLOWED_ORIGINS` = โดเมน Vercel / โดเมนจริง  
- คีย์ Omise (ถ้าเปิดชำระเงินจริง)

## ภาคผนวก ง หลักฐานการส่งลิงก์

- แคปหน้าจอการ์ดบน Padlet ที่มี URL เว็บไซต์  
- วันที่และชื่อผู้ส่ง
